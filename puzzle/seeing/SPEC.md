## 0. 설계 헌장 — 모든 판단의 기준

이 프로젝트의 모든 구현 판단은 아래 세 줄로 회귀한다.

1. **상태는 재현하고, 형질은 측정하고, 내용은 강요하지 않는다.**
   퍼즐로 '아하'라는 상태를 만들어내고, 그로 인한 '시야'의 변화를 재되, 무엇을 깨달아야 하는지는 절대 지시하지 않는다.
2. **유형은 입구, 유연성은 출구.**
   유형 결과는 공유를 부르는 미끼일 뿐, 최종 메시지는 항상 "당신 유형의 사각지대"다. 유형에 우열은 없다.
3. **확신은 진리를 보증하지 않는다 — 를 말이 아니라 체험으로.**
   거짓 통찰 함정 1개를 반드시 포함한다. 이 게임과 시중 자기계발 콘텐츠를 가르는 지점이다.

측정 대상은 사토리(궁극적 각성)가 아니라 **순간적 통찰(aha)**이다. 사토리는 과학적으로 정의조차 안 된 대상이므로 다루지 않는다.

**4~6분짜리 통찰 퍼즐 5종을 풀면, 나의 '통찰 스타일'(6유형)과 이번 판에서 '시야각이 몇 도 넓어졌는지'를 알려주는 모바일 웹게임.**

## 2. 사용자 흐름 — 순서 = 감정 설계이자 측정 설계

```
[인트로] → [사전 태도 3문항] → [p1_rat] → [p2_wason] → [p3_trap] → [p4_ninedot]
→ [p5_reframe] → [결과 카드 + 공유/JSON] → (선택) [M3 연구 동의]
```

| # | 화면 | 감정 비트 | 측정상의 필연성 |
|---|---|---|---|
| 1 | p1_rat | **워밍업** — "아, 이런 게임이구나" | T3의 함정 이전 확신 기준선 1/2 |
| 2 | p2_wason | **자신감 정점** — "내가 규칙을 찾아냈다" | 기준선 2/2, 유일한 행동 지표 공급 |
| 3 | p3_trap | **균열** — '맞다는 느낌'이 배신하는 순간 | 처치 시점. 앞 2개·뒤 1개의 확신 표본이 있어야 T3가 성립 |
| 4 | p4_ninedot | **큰 실패와 해방** — 마지막 획이 상자 밖으로 | T3의 유일한 사후항. 함정을 4번째로 옮기면 사후 표본이 0이 되어 T3가 통째로 폴백된다 |
| 5 | p5_reframe | **회복과 착지** — 정답이 없고 다시 봐도 되는 화면 | T1 단독 부양 |

3번(균열)과 4번(실패)을 연달아 둔 것이 의도다. 9점의 실패는 **해답이 아름답기 때문에** 해방으로 바뀐다. 그 뒤 재프레이밍이 와야 세션이 자책이 아니라 재해석으로 닫힌다.

**왜 5개인가** — 각 퍼즐이 부양하는 지표: p1=RHY·CNF·T2·T3기준선·T4 / p2=RHY·CNF·T2·T3기준선·T4·행동지표 / p3=CNF·RHY(거짓 아하)·T3 처치 / p4=RHY·CNF·T2·T3사후항·T4 / p5=T1 단독. **어느 하나를 빼도 최소 한 개 지표가 폴백으로 내려간다.**

화면 전환은 항상 한 방향(뒤로가기 없음), 이탈 시 `localStorage`에 진행 상태 저장.

**최악 경로 재계산** — 타임박스 합 345초 + `idle_grace_s(20)`×5 = 100초 + 비타임박스 구간(인트로 12 + 사전 22 + 확신·아하·기지·공개 약 100 + 결과 22) ≈ **601초**. 따라서 캡은 다음과 같이 동작한다.

- 캡의 시계는 **활성 시간** `active_total_ms = (now − ts_start) − session.hidden_ms − session.blocked_ms`이며, **화면 전환 시점에만** 검사한다(진행 중인 화면을 중간에 끊지 않는다). 이어하기 시 리셋하지 않고 이어서 누산한다.
- `soft_cap_s(360)` 초과 → 잔여 퍼즐의 타임박스를 `soft_cap_shrink(0.6)`배로 압축하고 `cap_soft=true`.
- `hard_cap_s(480)` 초과 → 남은 퍼즐을 **지표 손실이 가장 적은 순서로** 건너뛴다: ① `p2_wason`(타임박스 최장, T2·T3 pre에 각각 대체 표본 있음) ② `p1_rat` ③ `p3_trap` ④ `p4_ninedot`. **`p5_reframe`은 절단 예외**(T1 단독 부양원이므로 항상 제시). 건너뛴 화면은 `skipped:[]`에 적재하고 `dropped_at`·`cap_truncated=true`를 남긴다.
- 절단된 퍼즐은 `presented=false`로 기록되며 §6-2 총점 규칙에 따라 **항 제외 + 재스케일**된다(불이익 없음).
- 인트로·사전 태도·결과·동의 화면은 캡 검사 대상이 아니다.
- 타임박스 카운트다운은 `t_first_input`부터 시작하되, 첫 입력이 없으면 화면 진입 + `idle_grace_s(20)` 후 시작한다. **stall 계산 창의 시작점(`t_start`)과는 다른 기준임에 주의**(§5-1).

### 2-2. 척도류 입력 예산 — 척도 입력 13회 (상한 15)

| 구간 | 방식 | 회차 |
|---|---|---|
| 사전 태도 A1·A2·A3 | 2D 탭패드(x=동의도, y=확신도) ×3 | 3 |
| 제출 확신도(채점 입력) | 탭바 ×4 — p1, **p2 4지선다 선택 직후**, p3, p4 | 4 |
| p2 서술 확신도(`extra.conf_rule`, 연구 전용) | 탭바 ×1 | 1 |
| 아하 | 2D 탭패드(x=쾌감, y=갑작스러움) ×3 (p1, p3, p4) | 3 |
| 재프레이밍 판단 | 2D 탭패드 ×2 → 원값 4개 | 2 |
| **합계** | | **13** |

3차원 풀 슬라이더 0회. 함정 교체 분기에서 폐기되는 입력 최대 2회는 채점에 반영되지 않으므로 예산 외로 명시한다(실입력 최대 15 = 상한). 기지 확인("본 적 있나요?") 예/아니오 1탭은 척도가 아니므로 예산 외.

**제출 확신도 4회는 만료·포기 경로에서도 유지된다** — 해답 공개 직전에 동일 탭을 받으므로 경로와 무관하게 항상 4회다(§4 공통 규칙).

**슬라이더·탭 규약(필수)** — 핸들 없이 시작 → 최초 터치 전 '다음' 버튼 비활성 → `touched:true` 저장 → 미터치 항목은 **모든 평균·Brier의 분모에서 제외**. 값이 존재해도 `touched=false`면 계산에서 뺀다(기본값 50이 데이터를 오염시키는 경로 차단).

**척도 화면 이탈 방지(필수)** — 최초 터치 전 다음 버튼이 비활성이므로 무반응 사용자가 갇힌다. 따라서 모든 척도 화면은 `scale_idle_timeout_s(25)` 경과 후 **'건너뛰기'를 노출**하고, 누르면 `touched=false`로 저장한 뒤 다음 화면으로 넘어간다. 이것이 폴백 표의 `touched=false`에 도달하는 **정상 경로**다. 2D 탭패드 출력은 `pad_quantize(5)` 격자로 양자화해 손가락 노이즈가 값이 되지 않게 한다.

## 3. 사전 태도 3문항 (연구 공변량 전용)

각 문항을 **2D 탭패드 1탭**으로 받는다: x = 동의도(−50 매우 반대 ~ +50 매우 동의), y = 확신도(0~100).

| # | 문항 | 선정 이유 |
|---|---|---|
| A1 | "재능은 노력보다 중요하다" | 논쟁적이되 비정치·비종교 |
| A2 | "돈으로 행복을 살 수 있다" | 상동 |
| A3 | "MBTI 같은 성격 유형 검사는 과학적이다" | 게임 자체를 겨누는 메타 문항 |

**정치·종교·젠더·지역 관련 문항은 금지.** **사후 재질문은 삭제한다** — 같은 문항을 5분 뒤 다시 물으면 앵커링·평균회귀·요구특성이 동시에 걸려 태도 변화가 아니라 측정 아티팩트를 잡게 된다. 사전 3문항은 **유형·시야각 어디에도 투입하지 않는다.** 원값만 저장하는 연구 공변량이며, **A3는 그마저도 모든 점수 계산에서 제외**한다.

## 4. 퍼즐 상세 (5종 확정 — 임의 추가·교체 금지)

### 공통 규칙

**상태 플래그 정의(불변식 포함)** — 다섯 플래그의 의미를 여기서만 정의하고 §5·§6은 이 술어만 소비한다.

| 필드 | 정의 |
|---|---|
| `presented` | 이 퍼즐 화면이 실제로 제시되었다. 하드캡 절단·`dropped_at` 이후면 `false` |
| `solved` | 사용자가 스스로 최종 답을 확정 제출/완성했다(정오 무관) |
| `correct` | 확정 제출한 답이 정답이다. 불변식 `solved=false → correct=false`, `revealed=true → correct=false` |
| `revealed` | **풀이를 끝내기 전에** 해답을 열람했다(만료·포기 경로). **확정 제출·4획 완성 이후에 자동으로 나오는 정답 공개·해설·판정 애니메이션은 `revealed`가 아니다** — p2·p4처럼 전원이 마지막에 정답을 보는 퍼즐에서 이를 `revealed=true`로 찍으면 아래 불변식이 `correct`를 전원 `false`로 만든다 |
| `timeout` | 타임박스 만료로 분기했다 |
| `gave_up` | 만료 **전**에 사용자가 '답 보기'(p5는 '넘어가기')를 눌렀다. 불변식 `gave_up=true → timeout=false` |
| `assisted` / `assist_level` | 결정적 힌트(level 2)를 실제로 열람했다 → `assisted=true, assist_level=2` |
| `skipped` | 제시되었으나 응답 없이 넘어갔다(`presented=true && !solved && !revealed`) |

- **타임박스**는 config `timebox_s`에 퍼즐별 `{scope, stage, s}`로 정의한다. **확신도 탭·기지 확인·아하 탭·해답 공개·추가 정보 열람 구간은 타임박스 대상이 아니다.**
- **만료 동작은 전역 규칙이 아니라 퍼즐별**(`config.timeout_action`)이다: `p1_rat` `reveal` · `p2_wason` **`advance`(정답 미노출)** · `p3_trap` `reveal_via_conf` · `p4_ninedot` `reveal` · `p5_reframe` `skip`. p2에 '답 보기'를 적용하면 4지선다 정답이 누설되어 `correct`·T2·T4가 통째로 오염되므로 **p2는 예외**다.
- **확신도 1탭은 경로와 무관하게 보장한다.** 자력 제출이면 제출 직전, 만료·포기면 해답을 노출하기 **직전에** 동일한 탭바를 받는다(문구: "답을 보기 전에 — 지금 떠오른 답, 맞을 것 같나요? / 답을 못 정했다면 낮게 두세요"). 척도 예산은 늘지 않는다(§2-2).
- **수동 포기 경로**: 타임박스 `manual_reveal_after_s(15)` 경과 후 '답 보기'(p5는 '넘어가기') 버튼을 상시 노출한다. 누르면 `gave_up=true` → 확신도 1탭 → 해답. 이 버튼이 `gave_up`을 세우는 **유일한** 상호작용이다.
- **재시도**: 타임박스 내 무제한 허용. `correct = attempts 중 하나라도 정답`. 확신도는 **최초 제출 직전 1회만** 수집한다.
- **힌트**: 2단계 사다리(은근한 힌트 → 결정적 힌트). **자동 노출하지 않는다** — `auto_offer_at_ratio [0.5, 0.8]` 시점에 힌트 버튼이 **활성화될 뿐 내용은 열리지 않으며**, 사용자가 누른 것만 `hints[]`에 기록한다. 자동 노출은 임패스가 길어지는 순간을 인위적으로 절단해 RHY의 행동 성분이 '힌트 스케줄'을 재게 만든다. 활성 퍼즐은 p1·p4뿐이다.
- **아하**는 퍼즐 직후 **2D 탭패드 1탭**(x=쾌감, y=갑작스러움). 대상은 p1·p3·p4. `aha.context ∈ {self_solved, after_reveal}`를 함께 저장한다 — 자력 통찰의 갑작스러움과 남이 알려준 답을 본 순간의 갑작스러움은 다른 구인이므로 §5-1이 이 필드로 분리 처리한다.
- **기지 확인**: p1·p2·p4는 **해답 공개 화면 하단**에 예/아니오 1탭 "이 문제, 전에 본 적 있나요?"를 둔다(공개 이후이므로 풀이에 영향 없음). p3만 회피 분기 때문에 공개 **전**에 묻는다. 결과는 `known_before`에 저장한다.
- 모든 입력 이벤트에 타임스탬프 로깅(§7). `visibilitychange`로 숨겨진 구간은 `hidden_spans`, **시스템이 강제로 대기시키는 구간**(해답 애니메이션, 판정 연출, 로딩)은 `blocked_spans`에 적재하고 **모든 시간 계산에서 차감**한다.
- 조기 종료(`dropped_at`) 시에도 §5-4·§6-3 폴백 표를 타고 partial/minimal 결과 카드로 착지한다.

### P1 `p1_rat` — 워밍업: 세 낱말의 공통점

- **제시어**: 물 / 눈 / 불 → **허용 정답: 길, 빛** (물길·눈길·불길 / 물빛·눈빛·불빛 — 둘 다 표준 한국어이므로 **정답을 하나로 놓고 정확 일치 채점하면 옳은 통찰이 오답 처리된다**).
- **허용 정답 집합은 필수 필드다.** 문항·정답·힌트는 전부 `config.rat_pool[]`에 두고 코드에 상수로 박지 않는다(`accept:["길","빛"]`). 향후 추가되는 모든 RAT류 문항도 `accept` 배열을 반드시 갖는다.
- **타임박스** 60초(`solve` 단계). **힌트** 2단계(자동 노출 없음, 버튼 활성화만).
  - ① "세 낱말 뒤에 똑같이 붙는 한 글자가 있어요."
  - ② "'물○·눈○·불○'이 **모두** 자연스럽게 말이 되는 한 글자면 됩니다. 답이 하나뿐인 문제는 아니에요." — 대체 정답이 존재하므로 힌트가 특정 한 글자를 지목하면 안 된다. 이 힌트를 열면 `assist_level=2`.
- **입력**: 한글 1어절 텍스트(`autocomplete`/`autocorrect`/`spellcheck` 모두 off) → 제출 직전 확신도 탭바 1탭 → 아하 2D 탭패드 1탭 → (공개 화면에서) 기지 확인 1탭.
- **판정**: `norm(s)` = `trim` → 공백 전량 제거 → 조사(`이/가/은/는/요`) 후행 제거 → NFC 정규화. `correct = config.rat_pool[id].accept.includes(norm(input))`. 타임박스 만료 → 확신도 1탭 → '답 보기' → `revealed=true, correct=false`, 아하 탭은 그대로 진행(`aha.context='after_reveal'`).
- **RAT 어휘 규약**: 잔여 RAT가 1개뿐이므로 "남는 RAT 간 공유 어휘 0" 제약이 구조적으로 자동 충족된다. 다만 `?selftest=1`에 **`rat_pool[*].cues ∪ rat_pool[*].accept` 전 문항 교집합 = 0** 검사를 상시 배치해 향후 문항 추가 시 회귀를 막고, **대체정답 케이스("빛" 입력 → `correct=true`)를 픽스처 1건으로 고정**한다.
- **부양 지표**: RHY stall 1/3, RHY sudden 1/3, CNF 표본 1/4, T2 Brier 1/3, T3 이전 기준선 1/2, T4 성과 1/3. 연구 전용(점수 미반영): `aha.pleasure`, `attempts[]`, `t_first_input`, `hints[]`.

### P2 `p2_wason` — 2-4-6: 규칙을 찾아라

- **화면**: "2, 4, 6은 어떤 숫자 규칙을 따릅니다. 세 숫자를 제출해 규칙을 탐색하세요." **실제 규칙: 앞의 수보다 커지기만 하면 된다.**
- **타임박스** 90초(`tests` 단계) + 20초(`choice` 단계). **힌트 없음.** **아하 탭 없음** — 4지선다는 '번쩍'이 아니라 '확인'에 가까워 아하 평정이 가장 모호한 지점이다.
- **흐름(재배열 확정)**: ① 세 수 입력 반복(최소 3회, 회차마다 "규칙에 맞음/아님" 즉시 표시) → ② 1줄 자유 서술로 규칙 진술(*"설명이 어려우면 건너뛰기"* 허용, 건너뛰면 `rule_text=null`) → ③ **서술 확신도** 탭바 1탭(`extra.conf_rule`, **연구 전용**) → ④ 다음 화면에서 4지선다 제시, 화면 문구는 **"당신이 찾은 규칙에 가장 가까운 것을 고르세요"** → ⑤ **선택 직후 확신도 탭바 1탭**(`conf`, 채점 입력) → 정답 공개 → 기지 확인 1탭.
- **확신도의 지시 대상 정정**: ③의 확신은 '내가 서술한 규칙'에 대한 것이고 `correct`는 ④의 재인(recognition) 과제로 판정된다 — 자유회상과 재인은 난이도가 달라 두 값을 짝지으면 T2가 다른 구인을 잰다. 따라서 **T2·CNF·T3 pre는 ⑤의 `conf`를 쓰고**, ③은 `extra.conf_rule`로만 저장한다.
- **타임박스 만료 처리(`advance`)**: ①에서 만료되면 "지금까지의 느낌으로 답해 주세요" 안내와 함께 **최소 3회 제출 게이트를 해제**(`min_tests_waived_on_timeout=true`)하고 ②→③→④→⑤로 그대로 진행한다. **'답 보기'는 p2에 적용하지 않는다**(④의 정답 공개가 그 역할을 대체). ④에서 만료(20초)되면 `declared_choice_id=null, correct=null`로 저장하고 T2·T4의 **항목(item)에서만** 제외한다(항 제외가 아니다).
- **4지선다**(정답 = id 3, 표시 순서 셔플. 네 보기를 동일 문형·동일 길이·동일 어휘 밀도로 작성해 정답 누설 차단):
  - id1 앞의 수보다 2씩 커지는 세 수 — `b-a===2 && c-b===2`
  - id2 앞의 수보다 커지는 짝수 세 수 — `a<b && b<c && a%2===0 && b%2===0 && c%2===0`
  - id3 앞의 수보다 커지기만 하는 세 수 — `a<b && b<c` ← **정답**
  - id4 앞의 수와 다르기만 하면 되는 세 수 — `a!==b && b!==c`
  - **id4는 id3과 같은 완화 문형이다.** v0.2 초안의 "2배씩 커지는"은 구체 제약이라 '가장 느슨한 보기 하나'가 시각적으로 튀어 함정을 모르는 사용자에게도 정답이 누설됐다. 보기 문구·판정함수 쌍은 `config.wason.choices[]`로 빼서 M2-b에서 교체 가능하게 한다.
- **판정**: `correct = (declared_choice_id === config.wason.answer_id)`. `extra`에 **고정 id**(`declared_choice_id`)와 **표시 순서**(`shown_order:[3,1,4,2]`)를 함께 저장한다(위치 인덱스만 저장하면 사후 재구성이 불가능하다).
- **positive_test_ratio 조작적 정의**(연구 변수 전용, 점수 미반영). 두 정의를 모두 로깅한다. `pos_declared` = (사용자가 최종 선언한 보기의 판정함수를 만족하는 제출 수)/(총 제출 수), 선언이 없으면 `null`. `pos_seed` = (등차를 유지한 제출 수, `b-a === c-b`)/(총 제출 수) — 폴백 정의.
- **부양 지표**: RHY stall 2/3, CNF 표본 2/4, T2 Brier 2/3, T3 이전 기준선 2/2, T4 성과 2/3. 연구 전용: `tests[]`, `rule_text`, `pos_declared`, `pos_seed`.

### P3 `p3_trap` — 함정 라운드: 확신은 진리를 보증하지 않는다

게임의 감정적 핵심. **힌트 없음**(힌트는 함정을 무너뜨린다). 타임박스 45초(풀이 구간).

- **CRT 3문항 풀** (`trap_pool`, **첫 출제는 풀에서 균등 랜덤** `trap_first:'random'` — 가장 유명한 문항을 전원이 먼저 만나면 기지·스왑 발생률이 구조적으로 높아져 함정이 '처치'로 작동하지 않는 세션이 대량 발생한다)
  1. `bat_ball` — "야구방망이와 공을 합치면 1,100원입니다. 방망이는 공보다 1,000원 비쌉니다. 공은 얼마일까요?" **정답 50**(직관 오답 100)
  2. `race_second` — "달리기 경주에서 당신이 2등을 추월했습니다. 지금 당신은 몇 등일까요?" **정답 2**(직관 오답 1)
  3. `sheep_left` — "농부에게 양이 15마리 있었습니다. 8마리를 **제외하고** 모두 죽었습니다. 몇 마리가 남았을까요?" **정답 8**(직관 오답 7) — 확정 제약 H의 "그 외 인지도 낮은 1종"에 해당한다. v0.2 초안의 `water_tank`는 오히려 원조 CRT 3문항 중 하나라 제약을 위반했으므로 교체한다.
- **흐름**: 숫자 키패드 입력 → 확신도 탭바 1탭 → **"이 문제, 본 적 있나요?"** 예/아니오 1탭(척도 아님) → '예'면 즉시 풀의 **아직 제시되지 않은** 문항으로 **1회 교체**(`trap_max_swap=1`) → **아하 2D 탭패드 1탭(공개 직전)** → 공개 화면(4분기 카피).
- **아하를 공개 전에 받는 이유**: 공개 후에 물으면 사용자는 이미 자기 답이 틀렸음을 알고 있어, 찍히는 값이 '틀린 답이 떠올랐을 때의 갑작스러움'(= 거짓 아하의 강도, 헌장 §0의 원칙 3번 핵심 데이터)이 아니라 '해설을 본 순간의 갑작스러움'이 된다. 문구: "답이 떠올랐을 때, 얼마나 갑자기·얼마나 시원했나요?" `aha.context='self_solved'`.
- **스왑 소진 분기는 '진행'으로 통일한다.** 교체본도 기지이거나 스왑을 이미 썼으면 **라운드를 건너뛰지 않고** `known_before=true`로 그대로 풀게 한다(확신·아하 수집 정상 → CNF 4/4, sudden 3/3 유지). 공개 화면 카피만 기지자용으로 분기한다. 스왑으로 폐기된 1회차 입력은 `extra.discarded:{item_id, conf, answer_raw, aha}`에 **원값을 보존**하되 모든 채점에서 제외한다.
- **타임박스 만료(`reveal_via_conf`)**: p3는 공통 규칙의 '답 보기 즉시 노출' 예외다. 정답이 먼저 공개되면 확신도 탭·기지 확인·처치 시점이 모두 사라져 함정 자체가 무너진다. 만료 시 '답 보기'가 아니라 **`모르겠어요 / 대충 찍어볼게요`** 버튼을 노출하고, 어떤 경로로도 **확신도 탭 → 기지 확인 → 아하 → 공개** 순서를 반드시 통과시킨다. 무응답이면 `answer_raw=null, correct=false, timeout=true`이며 `conf.touched`는 정상 수집된다.
- **연출**: 다른 퍼즐과 동일한 축하 애니메이션 직전까지 진행한 뒤 판정한다. 조롱·감점 연출 절대 금지.
- **공개 화면 카피(4분기, 글자 그대로 유지)**
  - **오답자** ① "방금 확신도 {conf}을 주셨어요." ② "**틀렸다는 게 중요한 게 아니라, '맞다는 느낌'이 이렇게 강할 수 있다는 게 중요합니다.** 깨달음의 느낌은 진리의 보증서가 아니거든요." ③ 그 다음에 풀이.
  - **정답자** "이 문제는 먼저 떠오르는 답과 맞는 답이 갈리는 자리예요. 이번엔 그 갈림을 그대로 지나오셨네요. 방금 주신 확신도 {conf}도 함께 기록해 두었습니다." — v0.2 초안의 "많은 분이 같은 자리에서 다른 답을 냅니다"는 §9가 금지한 **타인과의 비교**이므로 삭제하고, 오답자 카피와 동일하게 확신도 원값을 되비추는 구조로 맞춘다.
  - **기지자**(스왑 소진 포함) "이미 아는 문제라도, 확신이 어떻게 움직이는지만 볼게요. 점수에서 손해 보시는 일은 없습니다." — '이번 라운드는 그냥 지나갈게요'는 흐름 서술과 모순이므로 삭제.
  - **무응답자**(만료·`모르겠어요`) "답을 정하지 못한 채로 지나가는 것도 기록입니다. 방금 주신 확신도 {conf}이 그 순간의 솔직한 눈금이에요." — 오답자 카피의 '확신도를 주셨어요' 문장을 그대로 재사용할 수 없으므로 별도 분기가 필요하다.
  - v0.1의 "87%의 사람은…" 통계 카피는 **삭제**. 출처 없는 수치이므로 정성·구간 표현으로만 쓴다.
- **부양 지표**: CNF 표본 3/4(성향 표본으로 대표성이 가장 높다), RHY sudden 2/3(= '거짓 아하'의 강도, 헌장 §0의 원칙 3번 핵심 데이터), T3의 **처치 그 자체**, T3 유효 조건 트리거(`presented`, `known_before`, `swapped`).
- **명시적 제외**: `p3_trap`은 **T2(Brier)·T4(성과) 어디에도 넣지 않는다.** 설계상 강한 확신과 오답을 유도해 놓고 그 오답으로 감점하는 것은 §9 정면 위반이며, T3가 이미 함정의 효과를 재고 있으므로 이중 계상이다.

### P4 `p4_ninedot` — 아홉 개의 점: 상자 밖으로 나가는 마지막 획

- 3×3 점 배열을 **한붓그리기 직선 4개**로 모두 통과. 타임박스 70초(`draw` 단계). 힌트 2단계(자동 노출 없음) — ①"선이 꼭 점에서 끝나야 할까요?" ②상자 밖으로 나간 예시 1획 표시(열면 `assist_level=2`).
- **좌표계·앵커 격자(필수 명세)** — 앵커 위치를 구현자가 임의로 잡으면 **정답 경로가 존재하지 않는 퍼즐**이 나온다. `config.ninedot`에 다음을 고정한다.
  - `grid:{n:3, spacing_units:100, origin:[0,0]}` — 실점 9개는 `(x,y) ∈ {0,1,2}²`(units로는 0/100/200).
  - `outer_anchor_rings:1`, `anchor_step_units:100` → 탭 타깃은 **5×5 확장 격자(x,y ∈ {−1,0,1,2,3})의 25개**이며, 그중 실점 9개를 뺀 **바깥 16개**를 옅은 점(또는 투명 히트박스)으로 렌더한다.
  - **판정은 units 공간에서** 수행한다. `hit_radius_units:22`(= `spacing_units`의 0.22). 렌더 시 units→px 스케일만 적용하므로 뷰포트(390px·태블릿·데스크톱 중앙 카드)가 달라져도 판정 난이도가 변하지 않는다. 실제 사용된 px 반경은 `extra.hit_radius_px`에 계속 로깅한다.
  - **불변식**: `hit_radius_units < anchor_step_units / 2` (인접 앵커 오탭 방지). 22 < 50 ✔
  - **표준 4획 해답 좌표(격자 인덱스, y는 위쪽이 +)**: **`(0,0) → (3,0) → (0,3) → (0,0) → (2,2)`**. 커버 검증 — 1획 `(0,0)(1,0)(2,0)` / 2획 `(2,1)(1,2)` / 3획 `(0,2)(0,1)` / 4획 `(1,1)(2,2)` = 9점 전량, 연결성 충족. 경유하는 격자 밖 앵커는 `(3,0)`·`(0,3)` 두 개이며 **둘 다 ring 1에 존재해야만 해답이 성립한다**. 해답 애니메이션은 이 좌표열을 그대로 따른다.
- **입력(전면 교체)**: 꼭짓점 **탭** + **고무줄 미리보기**(다음 탭까지 선분 실시간 프리뷰). 위 5×5 앵커가 모두 탭 대상이어서 상자 밖 탐색이 물리적으로 가능하다. 최대 4획, 되돌리기 1단계. **자유 드래그 없음**(모바일 손가락 판정 실패율이 높아 '실패의 해방'이 아니라 '조작 짜증'이 된다).
- **판정**: ① **연결성** — `stroke[i].start`가 `stroke[i-1].end`와 **동일 앵커**여야 한다. 위반 시 `correct=false, extra.disconnected=true`(떨어진 선분 4개로 정답이 나는 구멍을 막는다). ② **통과** — 각 실점에 대해 선분–점 거리 ≤ `hit_radius_units`이면 통과. ③ 4획 이하로 9점 전부 통과 && 연결성 충족 시 `correct=true`.
- **확신 → 판정 순서**: 4획 완성 또는 타임박스 만료 시 **판정 공개 전** 확신도 탭바 1탭("지금 그은 선이 9개 점을 다 지났을까요?") → 판정/해답 애니메이션(`blocked_spans`에 적재) → 아하 2D 탭패드 1탭 → 기지 확인 1탭.
- **핵심 연출**: 해답 애니메이션에서 **마지막 획이 상자 밖으로 벗어나는 순간 0.8초 정지·강조**. 이 한 컷이 세션 전체의 감정 정점이다.
- **카피 전제**: **실패가 기본 경로**다. 실패 화면은 "못 풀었다"가 아니라 "상자가 어디 있었는지 보여드릴게요"로 연다. 성공 시에도 축하는 짧게, 상자 밖 은유를 한 줄로만 반영한다.
- **부양 지표**: RHY stall 3/3(퍼즐별 lo/hi 별도 정규화), RHY sudden 3/3, CNF 표본 4/4, **T3 함정 이후 확신 수준(핵심 사후항)**, T2 Brier 3/3, T4 성과 3/3. 연구 전용: `strokes[]`, `vertices_tapped`, `out_of_box_first_t`, `hints[]`.

### P5 `p5_reframe` — 다시 보기: 한 장면, 두 번의 판단

**퍼즐이 아니다.** 판단 갱신 자체가 지표이므로 아하를 수집하지 않는다. 타임박스 60초(`judge_pre` 단계 — **추가 정보를 읽는 구간에는 걸리지 않는다**), 만료 시 '답 보기'가 아니라 **'넘어가기'**를 노출한다. **하드캡 절단의 예외**로 항상 제시된다(T1 단독 부양원).

- **1단계 장면**(`reframe_scenario: "absent_colleague"`)
  > 같은 팀 동료 J가 오늘 아침 회의에 말없이 나타나지 않았습니다. 연락도 없었습니다. 이번 달만 세 번째입니다. 팀은 J가 맡은 자료 없이 회의를 진행했습니다.
- **판단 입력**: 2D 탭패드 1탭 — x = "J는 팀에 무책임하다"에 대한 동의도(−50~+50), y = 확신도(0~100).
- **2단계 추가 정보 1문단**
  > 회의가 끝난 뒤 J에게서 메시지가 왔습니다. 지난달 계정 이관 과정에서 J의 사내 알림이 통째로 꺼져 있었고, 오늘 회의는 어제 저녁에 시간이 옮겨진 것이었습니다. J는 원래 시간에 맞춰 빈 회의실에 혼자 앉아 있었습니다.
- **3단계 재평가**: 동일 탭패드로 1탭. **안 바꿔도 감점·재촉 없다.** 판단을 "고치라"고 요구하지 않고 재평가 기회만 준다.
- **'바꾸지 않기(그대로 두기)' 버튼을 명시적으로 제공한다.** §2-2 규약상 사후 탭패드도 핸들 없이 새로 찍어야 하므로 '판단을 안 바꿈'을 정확히 표현할 방법이 없고, 같은 자리를 다시 찍어도 Δ가 3~5씩 나와 노이즈가 점수로 지급된다. 이 버튼을 누르면 `touched_post=true, changed=false`, `agree_post=agree_pre`, `conf_post=conf_pre`로 확정한다. **앵커링 방지를 위해 사전 위치 마커는 표시하지 않는다.** 탭 입력은 `pad_quantize(5)` 격자로 양자화하고 `deadzone(5)` 미만 Δ는 0으로 처리한다.
- **소재 규약**: v0.1의 코비 지하철 일화는 삭제한다(지나치게 유명 + 부모 사망 소재). 시나리오는 `config.reframe_scenario`로 교체 가능하며, **무거운 소재로 교체할 때만** 직전에 예고 1줄(`reframe_warn_line: true`)을 노출한다. 현 시나리오는 예고 불필요(`false`).
- **부양 지표**: **T1 신념 갱신폭의 단독 부양원**. 원값 4개(`agree_pre, conf_pre, agree_post, conf_post`)와 `touched` 4개를 각각 별도 저장한다. 연구 전용: conf 변화량, `changed` 불리언, `t_info_shown`.
- **축 미투입**: 어떤 유형축에도 넣지 않는다(1문항 서사 지표로 카테고리를 비교하지 않는다).

## 5. 유형 시스템 — 통찰 스타일 6유형

### 5-1. 두 축

정답 여부는 **두 축 어디에도 쓰지 않는다.** 정확성(보정)은 시야각 T2가 전담하고 유형축은 성향만 담당한다 — 이 분리선이 헌장 §0의 원칙 2번("유형에 우열은 없다")을 구조적으로 보장한다.

#### 축 1 — RHY 도달 리듬: 번쩍(F) / 스밈(G)

```
rhythm_index = w_stall·q_stall(stall_norm) + w_sudden·q_sudden(sudden_norm)
판정: rhythm_index ≥ (모드별 컷) → 번쩍(F), 미만 → 스밈(G)
```

두 성분을 **원 스케일 그대로 평균 내지 않는다.** `stall_norm`은 lo/hi로 0~1에 펴 놓은 값이고 `sudden_norm`은 자기보고 원값/100이라 분포 중심이 다르다(자기보고 갑작스러움은 통상 상단에 몰린다). 그대로 평균하면 중앙값이 0.5를 크게 넘어 F가 65~75%로 쏠려 §10 M2-b 분포 게이트를 산술적으로 통과할 수 없다. 따라서 각 성분을 config에 저장된 **참조 분포로 분위수 매핑**한 뒤 합성한다: `q_stall`·`q_sudden`은 `config.axis_rhythm.stall_ref_q` / `sudden_ref_q`(각 11개 분위점 배열)에 대한 선형 보간 분위수. 컷은 상수가 아니라 **참조분포의 중앙값**이며 폴백 모드별로 분리한다(`cut_both` / `cut_behavior_only` / `cut_self_report_only`). 참조분포와 컷은 M2-b 실측에서 확정한다(§10).

- **stall_norm** — 대상 i ∈ {p1_rat, p2_wason, p4_ninedot}
  - **계산 창 = `[t_start_i, t_solve_end_i]`.** `t_solve_end` = 확정 제출 · 4획 완성 · `gave_up` · 타임박스 만료 중 **먼저 오는 시각**(신설 필드). `t_end`는 **화면 이탈 시각**으로 의미를 좁히고 stall 계산에 사용하지 않는다. 이 구분이 없으면 해답 애니메이션 12~17초가 전 사용자의 최장 공백이 되어 RHY의 절반이 사용자 행동이 아니라 **연출 길이**를 재게 된다.
  - **창의 시작은 `t_first_input`이 아니라 화면 진입(`t_start`)이다.** RAT는 답이 떠오른 뒤에야 타이핑하므로 p1에서 사고는 전부 진입~첫 타건 구간에서 일어난다. 이 구간을 빼면 40초 생각 후 2초 타이핑하는 전형적 '번쩍' 세션이 표본에서 탈락한다. `events[]` 맨 앞에 가상 이벤트 `{t:t_start, kind:'enter'}`를 넣어 첫 공백이 계수되게 하고, `pre_input_gap_ms`도 원값으로 별도 저장한다. **타임박스 카운트다운의 기준(`t_first_input` + `idle_grace`)과는 다른 기준임을 구현 시 혼동하지 말 것.**
  - `active_ms_i = (t_solve_end_i − t_start_i) − hidden_ms_i − blocked_ms_i`. `stall_ratio_i = longest_stall_ms_i / active_ms_i`.
  - **유효 조건** = `active_ms_i ≥ config.stall.min_active_ms(5000)`(**화면 체류 기준**, '입력 후 경과'가 아니다) **그리고 활동 증거** `attempts.length ≥ 2 || correct || hints.length ≥ 1 || (p4는 strokes.length ≥ 2)`. **`attempts[]`는 전 퍼즐 공통 필드다** — p1 = 텍스트 제출, **p2 = `extra.tests[]`의 세 수 제출을 `attempts[]`에도 같이 적재**(적재하지 않으면 p2가 활동 증거를 못 세워 stall 표본 2/3이 통째로 탈락한다), p3 = 숫자 제출, p4 = 획 확정(`strokes[]`와 병행 기록). `stall_ratio`는 이탈·방치와 impasse를 구별하지 못하고 오히려 방치가 최대값을 내므로(5초에 한 글자 치고 방치 → ratio 0.98 → 정규화 1.0 = 최대 번쩍), **입력 0의 무활동 타임아웃 세션은 표본에서 제외**하고 `stall_excluded_reason`을 로깅한다.
  - `longest_stall_ms_i`는 **`events[]` 원값 배열에서 매번 재계산**한다(저장된 파생값을 신뢰하지 않는다). `events=[{t,kind}]`, `kind ∈ enter|key|tap|submit|hint|pad|reveal|timeout`. 마지막 이벤트~`t_solve_end` 구간도 공백 후보에 포함하되 `min(gap, config.stall.tail_cap_ms(10000))`으로 절단한다. `hidden_spans`·`blocked_spans`와 겹치는 시간은 차감하고, `config.stall.min_gap_ms(1500)` 미만 간격은 stall로 계수하지 않으며, `hints[k].t` 이후 구간은 별도 세그먼트로 취급해 **최장 공백 후보에서 제외**한다(힌트 열람이 임패스를 인위 절단하는 오염 차단). 판정 규칙 자체를 `stall_rule_version`으로 로깅해 계수 변경 시 과거 세션 재채점이 가능하게 한다.
  - **퍼즐별 정규화** `clamp01((stall_ratio_i − lo_i)/(hi_i − lo_i))`, lo/hi는 `config.stall.norm`에 퍼즐별 분리 — 입력 양식이 달라 원 비율을 그대로 평균 내면 9점이 축을 지배한다. **창 정의가 바뀌었으므로 lo/hi 초기값은 잠정치이며 M2-b 실측 분위수로 재설정한다.** `stall_norm` = 유효 항목의 정규화값 평균(분모는 **유효 항목 수**).
  - 연구 전용 병용 지표 `gap_rate` = (`min_gap_ms` 이상 공백 개수) ÷ (활성 분). 축에는 투입하지 않고 M2-b에서 `stall_ratio`의 대체 정의 후보로만 평가한다.
- **sudden_norm** — `aha.touched=true`인 항목의 `aha.sudden/100` 평균. 대상 {p1_rat, p3_trap, p4_ninedot}, 최대 3항목. **`aha.context='self_solved'`인 항목만 평균한다.** 자력 통찰의 갑작스러움과 남이 알려준 답을 본 순간의 갑작스러움은 다른 구인이므로 섞지 않는다(p3의 아하는 §4 P3에 따라 **공개 직전**에 수집되므로 `self_solved`에 해당한다). `self_solved` 표본이 0이면 `after_reveal` 항목을 포함하되 `sudden_mode='revealed_only'` + `low_n=true`를 기록한다(원값은 어느 경우에도 계속 저장).
- **원천 필드 전량**: `events[]`, `hidden_spans[]`, `blocked_spans[]`, `hidden_ms`, `t_start`, `t_first_input`, `t_solve_end`, `stall_rule_version`, `aha.{sudden,touched,context}`, `config_version`.

#### 축 2 — CNF 확신 배분: 단언(D) / 가늠(M) / 유보(R)

```
conf_mean = conf.touched=true 인 퍼즐의 conf.v 평균 (대상 p1, p2, p3, p4 — 최대 4항목)
conf_mean ≥ config.axis_conf.cut_hi(68) → 단언(D)
conf_mean ≤ config.axis_conf.cut_lo(42) → 유보(R)
그 외                                   → 가늠(M)
```

- 컷은 **M2-b 실측 분위수**로 역산해 각 구간이 25~45%에 오도록 조정한다(**코드가 아니라 config만 수정**). 4문항 평균이라 분산이 줄어 고정 컷 42/68이 중간 구간을 70% 이상 삼킬 수 있으므로, 컷은 상수가 아니라 **참조분포의 33/67 분위**로 정의한다.
- 함정(`p3_trap`)의 확신도는 채점(T2)에는 안 쓰지만 **성향 표본으로는 가장 대표성이 높으므로 이 축에는 포함**한다.
- 원천 필드: `puzzles[].conf{v,touched,t}`, `config_version`.

### 5-2. 유형 6종 — 우열 없는 긍정 톤 (v0.1 빛 은유 계승)

`type_code = ${RHY}${CNF}` (FD/FM/FR/GD/GM/GR)

|  | 단언(D) | 가늠(M) | 유보(R) |
|---|---|---|---|
| **번쩍(F)** | **벼락** | **불꽃** | **반딧불** |
| **스밈(G)** | **등대** | **새벽** | **노을** |

한 줄 정의 — **FD 벼락**: 내리꽂히고, 내리꽂힌 자리를 믿는다 / **FM 불꽃**: 순식간에 붙지만 세기를 스스로 조절한다 / **FR 반딧불**: 자주 반짝이되 하나에 오래 머물지 않는다 / **GD 등대**: 천천히 자리를 잡고, 잡은 자리를 오래 비춘다 / **GM 새벽**: 서서히 밝아지며 밝기를 계속 가늠한다 / **GR 노을**: 천천히 물들고, 물든 색을 단정하지 않는다.

### 5-3. 결과 카피 — 축별 조각 조립 (6개 개별 작문 금지)

`잘하는 것` = RHY 조각, `사각지대` = CNF 조각. 이 조립으로 6종이 모두 생성된다.

| 축값 | 조각 |
|---|---|
| 번쩍(F) | 잘하는 것: "남들이 아직 재고 있을 때 이미 도착해 있습니다." |
| 스밈(G) | 잘하는 것: "답이 보이지 않는 구간을 견디며 조금씩 좁혀 갑니다." |
| 단언(D) | 사각지대: "내리꽂힌 확신은 검산을 건너뛰게 합니다." |
| 가늠(M) | 사각지대: "적당한 확신은 편해서, 틀렸을 때 되짚을 표시가 남지 않습니다." |
| 유보(R) | 사각지대: "확신을 아껴 두면 맞았을 때조차 그 답을 밀고 나가지 못합니다." |

예) **벼락** — "잘하는 것: 남들이 아직 재고 있을 때 이미 도착해 있습니다 / 사각지대: 내리꽂힌 확신은 검산을 건너뛰게 합니다."

추가로 **하이라이트 1줄**(`aha.pleasure`가 가장 높았던 퍼즐 이름)을 계산 주장 없이 서술로만 붙이되, `touched` 표본이 0이면 문장 자체를 생략한다.

**성과는 유형에 넣지 않고 시야각 숫자에만 넣는다.** 유형은 "어떻게 도달하는가"(성향), 시야각은 "이번 판에서 얼마나 움직였는가"(갱신·보정)다. 다만 **두 계열은 `puzzles[].conf.v`를 공유한다**(CNF축과 T2·T3가 같은 필드를 먹는다) — "서로 다른 필드를 먹으므로 겹치지 않는다"는 v0.2 초안의 진술은 사실이 아니었다. 따라서 규칙은 필드 분리가 아니라 **표현 분리**다: **확신에 관한 진술은 결과 카드에서 유형 쪽(사각지대 1줄)에만 노출하고 시야각 설명에는 쓰지 않는다.**

**분포 통제** — 확신축은 참조분포 33/67 분위, 리듬축은 참조분포 중앙값 컷. 두 컷 모두 **실측 분위수로 정의되므로** 정의상 각 축이 균등 분할되고, 축 상관 ρ=0.5에서도 최저 셀 ≈8%로 M2-b 분포 게이트(40% 초과·2% 미만 금지)에 여유가 남는다. **고정 상수 컷(0.50, 42/68)으로는 이 계산이 성립하지 않는다** — 그래서 컷을 분위수로 재정의했다.

**강등 사다리** — 트리거는 "재검사 70% 미달"이 아니라 **① 내적 일관성 기준 미달(아래) 또는 ② M2-b 실측에서 한 셀 40% 초과**다. 실행: ⓐ CNF 3분할 미달 → 중앙값 이진 분할로 접어 **4유형**(벼락/반딧불/등대/노을) ⓑ RHY 미달 → stall·sudden 중 안정성이 높은 성분 단독(가중 1,0 또는 0,1)으로 단순화 후 재측정 ⓒ 그래도 미달 → 유형 체계를 폐기하고 '시야각 + 공통 사각지대'만 실은 카드로 격하하고 유형 요건을 다음 버전으로 이월. 2유형으로 내려가 4~8 제약을 위반하느니 유형을 없애는 편이 정직하다.

**내적 일관성 기준(단일 세션 내, 실측 10명으로도 계산 가능)** — CNF: 4개 `conf.v` 항목의 split-half 상관 또는 α ≥ 0.5. RHY: `stall_norm` 항목(p1·p2·p4) 간 상관 ≥ 0.3 그리고 `sudden` 항목 간 상관 ≥ 0.3. 재검사(§10 M2-b DoD ⑤)는 확정 제약이므로 유지하되, **통찰 퍼즐의 2회차는 전 문항이 기지 문항이 되어 stall≈0·sudden 급락·확신 급등이 구조적으로 발생한다**. 따라서 재검사는 반드시 **동형 B폼**(`config.forms.b`의 RAT·CRT 대체 문항)으로 실시하고, B폼이 없는 `p4_ninedot`은 2회차에서 제외하며, 결과는 특성 안정성과 학습 효과 크기를 분리해 해석한다. n=10 이진 일치율의 표준오차가 약 15%p임을 명시해 7/10과 6/10을 가르는 판정으로 쓰지 않는다.

### 5-4. 축 폴백 표

결측을 0으로 채워 평균에 넣지 않는다. **분모는 언제나 유효 항목 수.** 모든 분기는 상수 또는 미판정으로 끝나며, 어떤 경로로도 `NaN`/`undefined`가 결과 카드에 도달하지 않는다.

**RHY는 표가 아니라 전수 분기 함수로 정의한다.** 조건 나열식 표는 `(n_stall, n_sudden)`이 `(1,0)`·`(0,1)`인 흔한 조기 이탈 세션을 어느 행에도 걸지 못하고, `n=1`을 결측으로 보는 행과 유효로 보는 행이 동시에 매칭되는 모순도 있었다. 아래 4분기는 **전 조합을 남김없이, 배타적으로 덮는다.**

```
n_stall, n_sudden = 각 성분의 유효 항목 수 (§5-1 유효 조건 통과분)
1) n_stall=0 && n_sudden=0 → 축 미판정: axes.rhythm.code=null, result.mode='partial', 리듬 문구 전면 생략
2) n_stall=0 && n_sudden≥1 → weights=(0,1), mode='self_report_only', cut=cut_self_report_only
3) n_sudden=0 && n_stall≥1 → weights=(1,0), mode='behavior_only',  cut=cut_behavior_only
4) 둘 다 ≥1           → weights=(0.5,0.5), mode='both',        cut=cut_both
공통: (n_stall + n_sudden) < config.axis_rhythm.low_n_below(3) → low_n=true, 카피를 '이번 판 기준'으로 한정
```

**모드마다 컷이 다른 이유**: 성분 분포가 서로 달라 같은 컷 0.50을 쓰면 `self_report_only` 사용자는 대부분 F로, `behavior_only`는 반대로 쏠려 **폴백 경로에서만** 분포 게이트를 위반한다. 세 컷은 M2-b에서 각 모드의 참조분포 중앙값으로 각각 역산한다.

**CNF도 단일 사다리로 통일한다.**

| n = `conf.touched` 항목 수 | 처리 | 대응 config |
|---|---|---|
| 0 | 축 미판정 → `result.mode='partial'` | — |
| 1 | 중립 수축 `conf_adj=(n·conf_mean + k·prior)/(n+k)` 후 판정 + `low_n=true` | `axis_conf.shrink_k(1)`, `shrink_prior(50)` |
| 2~3 | 판정 + `low_n=true` + 결과 카드에 "표본이 적어 참고용" 각주 1줄 | `axis_conf.low_n_below(4)` |
| 4 | 정상 판정 | `axis_conf.cut_lo/cut_hi` |

`min_items`라는 키는 **삭제한다** — "판정 가능 최소치"로 읽히면 위 사다리와 정면 충돌해 같은 세션이 구현자에 따라 다른 카드를 낸다. `low_n_below`(표본 충분 기준)로 개명했고, **미판정은 n=0에서만** 발생한다.

| 그 밖의 상황 | 감지 조건(로깅 필드) | 폴백 |
|---|---|---|
| 미터치 값 존재 | `touched=false` | 값이 있어도 모든 평균·Brier의 분모에서 제외 |
| 함정 미도달 | `p3_trap.presented=false` | 결과 카드 함정 줄 자체를 렌더링하지 않음(§6-1) |
| 두 축 모두 미판정 | RHY 1)번 && CNF n=0 | `result.mode='minimal'`: 유형·시야각 미표기, "여기까지의 기록" 카드 + JSON 다운로드 |
| 잔여 비수치 | `Number.isFinite` 실패 | 축 미판정으로 강제 이탈(방어선 2중화) + `degraded=true` 로깅 |

## 6. 결과 카드

### 6-1. 구성 요소 (위에서 아래로)

① 유형명 + 은유 아이콘 1종(SVG, 6종) ② **시야각**: "이번 판에서 시야각이 **+N°** 넓어졌습니다" ③ 잘하는 것 1줄 + **사각지대 1줄**(§5-3) ④ 함정 결과 한 줄: "확신 vs 진실 라운드: 통과 / 배움 / 이미 아는 문제 / **미도달**"(오답을 '배움'으로 표기, **'실패' 금지**) ⑤ 하이라이트 1줄(표본 있을 때만) ⑥ 하단 고지 1줄: "이 테스트는 오락과 연구 목적이며 심리 진단이 아닙니다" ⑦ 공유 버튼(§8-3) / "내 데이터 JSON 내려받기"

**일괄 규칙 — 카드에 들어가는 모든 문자열은 소스 값이 `null`이거나 표본이 0이면 문장(줄) 단위로 생략한다.** 빈 문자열·`undefined`가 카드에 도달하는 경로를 이 한 줄이 닫는다. ④의 '미도달'은 `p3_trap.presented=false`(하드캡 절단·이탈)일 때이며, 이 경우 문구를 쓰지 않고 **줄 자체를 생략**한다.

**`result.mode`별 카드 규격**

| mode | 헤드라인 | 본문 |
|---|---|---|
| `full` | 유형명 + 은유 아이콘 | ①~⑦ 전량 |
| `partial` | **`type_code`가 있으면 유형명 + 은유 아이콘을 그대로 쓰고, `null`이면 고정 문구 "이번 판의 기록" + 중립 아이콘 1종** (한 축만 판정되면 `type_code`가 만들어지지 않으므로 헤드라인이 사라지는 구멍을 막는다. `partial`은 '축 미판정'과 '시야각 미표기(`sum_max<15`)' 두 경로에서 발생하므로 헤드라인은 mode가 아니라 **`type_code` 존재 여부**로 결정한다 — 두 축이 다 판정된 채 시야각만 빠진 세션에서 멀쩡한 유형명을 숨기지 않기 위해서다) | 판정된 축의 조각 1줄만 노출, 미판정 축 문구·시야각(해당 시)은 생략 |
| `minimal` | "여기까지의 기록" | 유형·시야각 모두 생략, JSON 다운로드는 유지 |

어떤 폴백 카드에도 **"여기까지 잰 것만 더했어요" 한 줄**을 반드시 노출한다.

### 6-2. 시야각 공식 (배점 8+10+7+5 = 30)

**항 계산의 3단 계약(모든 항 공통)** — ① 유효 조건 판정 → ② 불충족이면 **사유별 분기**(아래 표) → ③ 충족일 때만 수식 평가. `safeDiv(a,b,fb)`의 `fb`는 **점수 산출 경로가 아니다**. 유효 조건에서 이미 분모 0이 걸러지므로, `fb`가 실제로 발동했다면 그것은 버그이며 `degraded=true`를 찍고 그 항을 제외한다.

| 사유 | 감지 | 처리 | `skip_reason` |
|---|---|---|---|
| 미제시 | 소스 퍼즐/문항이 전부 `presented=false` | **항 제외 + 재스케일** | `not_presented` |
| 제시됐으나 미응답 | `presented=true` && (미터치·미시도·건너뛰기) | **`score=0`으로 항 유지**(재스케일 대상 아님) | `no_response` |
| 처치 무효 | T3 전용 — `p3_trap.known_before` 또는 `p4.correct=true` | 항 제외 + 재스케일 | `no_treatment` |
| 측정 불가 | T3 전용 — `room_conf < min_room` | 항 제외 + 재스케일 | `no_room` |

**왜 이 구분이 필수인가** — 초안처럼 미응답까지 '제외 후 재스케일'하면 **건너뛴 사용자가 성실히 응답하고 안 움직인 사용자보다 높은 점수를 받는다**(예: T2 4.85+T3 2.8+T4 1.65 = 9.3인 두 사용자 중, p5에서 Δ=0을 찍은 쪽은 `sum_max` 30 → 9°, p5를 건너뛴 쪽은 `sum_max` 22 → 12.7 → **13°**). 스킵이 +4°의 보상이 되는 이 경로를 `presented`/`skipped` 분리가 닫는다.

#### T1 신념 갱신폭 — 8점

```
Δ_agree = |agree_post − agree_pre|                      // 5점 격자 양자화, deadzone(5) 미만은 0
dir     = Δ_agree === 0 ? 0 : sign(agree_post − agree_pre)
                                                         // dir=0 이면 upd_agree=0 으로 끝난다(항 전체를 0으로 만들지 않는다).
                                                         // 확신 경로 upd_conf 는 dir 과 무관하게 항상 평가한다 — 아래 근거 참조
room    = dir > 0 ? (50 − agree_pre) : (agree_pre + 50)  // 움직인 '방향'의 잔여 여지 ∈ [0,100] (dir=0 이면 미사용)
room_factor = clamp(config.fov.t1.room_factor_min(0.5), 1, room / config.fov.t1.room_ref(50))
upd_agree   = Δ_agree / (config.fov.t1.delta_full(30) × room_factor)
Δ_conf      = max(0, conf_pre − conf_post)               // 확신을 낮춘 것도 신념 갱신이다
upd_conf    = Δ_conf / config.fov.t1.conf_full(30)
score       = 8 × clamp(0, 1, max(upd_agree, upd_conf))
```
- **`room` 재정의 이유**: 초안의 `room = |agree_pre − opposite_end|`는 항상 50~100이라 clamp 후 0.833~1.0만 취했고 `room_factor_min:0.5`는 도달 불가능한 죽은 값이었다. 방향 여지 + `room_ref=50`으로 바꾸면 하한이 실제로 발동하고, 이미 극단에 걸어 둔 사용자도 정당하게 점수를 받는다.
- **확신 하락도 갱신으로 인정하는 이유**: 처음부터 J를 두둔한 사용자는 동의도를 움직일 곳이 없어, 방향 무관 채점만으로는 J를 더 비난해야 점수를 받는 도착이 생긴다. "판단은 그대로지만 덜 확신하게 됨"도 신념 갱신이므로 `max()`로 함께 인정한다(원값 4개는 이미 저장 — **필드 추가 없음**).
- **방향 무관** — 굳히든 뒤집든 '움직였다'만 본다. 안 바꾼 사용자는 0점, 감점 없음.
- 원천: `p5_reframe.extra.{agree_pre, conf_pre, agree_post, conf_post, changed}` + `touched_pre/post`. 유효 조건 `touched_pre && touched_post`. **p5 미제시** → 항 제외 + 재스케일 / **p5 제시됐으나 건너뛰기·미터치** → `score=0`으로 항 유지.

#### T2 세션 보정 (Brier) — 10점

```
items     = config.fov.t2.items 중
            conf.touched && (solved || revealed) && t_first_input != null
            && assist_level < 2 && known_before === false && correct !== null
brier     = mean_i( (conf.v_i/100 − correct01_i)² ) ∈ [0,1]
brier_adj = (n·brier + k·prior) / (n + k)     // k=shrink_k(1 / n=1이면 2), prior=brier_prior(0.25)
score     = 10 × (1 − clamp(0, 1, brier_adj / config.fov.t2.brier_max(0.5)))
```
- **함정(p3_trap)은 이 항에서 제외한다.** 정답률 자체가 아니라 확신–정답 정합만 본다. 하나도 못 맞혀도 확신을 낮게 걸었으면 만점이 가능하므로 성적 랭킹이 아니다.
- **`known_before=true` 항목과 결정적 힌트(`assist_level=2`) 항목을 뺀다.** 9점·2-4-6은 세계에서 가장 널리 알려진 과제라 기지자는 고확신·정답으로 Brier를 왜곡한다. 힌트 ②는 사실상 정답 공개인데 그 뒤 제출은 `correct=true`가 되어, 같은 '정답을 받아본' 상태가 경로에 따라 정반대로 취급되는 구멍이 있었다.
- **`correct=null`(p2 4지선다 미응답)은 항목에서만 제외**하고 항은 유지한다.
- 유효 조건 `n ≥ 1`. `n=1`이면 `shrink_k=2`로 강하게 수축하고 `low_n=true`. `n=0`이면 위 3단 계약의 사유 분기를 탄다.
- 원천: `puzzles[].conf{v,touched}`, `correct`(`solved`와 분리), `revealed`, `assist_level`, `known_before`.

#### T3 확신 조정폭 — 7점

```
pre       = mean(conf.v of p1_rat, p2_wason | touched=true)
post      = p4_ninedot.conf.v (touched=true)
drop      = pre − post
room_conf = max(0, pre − config.fov.t3.conf_floor(10))
score     = 7 × clamp(0, 1, drop / min(config.fov.t3.drop_full(25), room_conf))
```
- **표기명을 '함정 이후 확신 조정' → '확신 조정폭'으로 바꾼다.** 통제 조건이 없어 함정 귀인이 불가능하고, p4 난이도로 인한 자연 하락과 완전히 교락되어 있다. 이 편의는 `drop_full` 계수로 흡수한다.
- **여지 보정(`room_conf`)이 필수인 이유**: `drop = pre − post`는 `pre` 수준에 상한이 걸려 있어, 확신을 낮게 거는 사용자(CNF 유보 R)는 구조적으로 드롭 여지가 없다. 보정이 없으면 "유보형은 시야각이 낮다"는 **사실상의 유형 서열**(§9 위반)이 생긴다.
- **`trap_floor`(보장 바닥 4점)는 삭제한다.** 처치를 받지 않은 집단(기지자)과 함정 정답자에게 순이득을 주어, 확신을 전혀 낮추지 않은 두 사용자 사이에 4점 차가 생기고 그 방향이 헌장과 반대였다(처치를 받은 사람이 불리). 대신 **항 제외**로 처리하면 상한 30이 그대로 보장되면서 부당 이득이 사라진다.
- **유효 조건**: `pre 표본 ≥1` && `post.touched` && `p3_trap.presented && known_before===false` && **`p4_ninedot.correct === false`** && `room_conf ≥ config.fov.t3.min_room(8)`.
  - `p4.correct=true`를 제외하는 이유: p4를 실제로 푼 사용자는 높은 확신을 유지하는 것이 **정확한 보정**이라 T2에서 보상받는데, 바로 그 값이 T3의 `post`가 되어 7점을 통째로 잃는다. T2와 T3가 같은 값을 반대 방향으로 채점하는 교착을 이 조건이 푼다(정답자에게는 확신 하락이 정상 반응이 아니므로 애초에 측정 대상이 아니다).
  - 정답자는 결과 카피에서 '통과'로 인정하되 **점수로 보상하지 않는다**.
- **정답 공개 직후의 확신 재질문은 채택하지 않는다.** 정답을 보여준 뒤 "지금 확신은?"을 물으면 전원이 낮게 답해 분산이 0이 된다(사후 태도 재질문 삭제와 같은 요구특성 결함). 이 항은 재질문 없이 **다음 라운드의 자연스러운 확신 수준**만으로 계산한다.

#### T4 해결 성과 — 5점

```
attempted     = config.fov.t4.items 중
                presented && known_before === false && (solved || revealed)
                && t_first_input != null && correct !== null
correct_count = 그중 (correct && assist_level < 2) 인 수
유효 조건: attempted ≥ 1
score         = 5 × correct_count / attempted        // attempted ≥ 1 일 때만 평가
```
- `attempted`를 **`t_first_input` 기준이 아니라 `presented` + 종료 상태 기준**으로 정의한 이유: 초안대로면 "시도하지 않으면 분모에서 빠진다"는 구멍이 생겨 무시도가 유리해진다. `attempted=0`은 3단 계약의 사유 분기를 탄다(제시됐는데 0이면 `score=0` 항 유지, 미제시면 항 제외).
- 타임박스 만료 후 '답 보기'로 진행한 경우 `revealed=true & correct=false`로 기록해 분모에는 넣되 정답으로 세지 않는다(원값 두 개를 각각 저장, 파생 플래그 하나로 합치지 않는다).
- **30점 중 5점(1/6)으로 배점을 눌러 둔 것이 설계 의도다.** 9점 문제는 실패가 기본 경로이므로, 아무것도 못 푼 사용자도 T1~T3만으로 목표 중앙값 12~18 구간에 진입할 수 있어야 한다.

#### 총점 규칙

```
valid_terms = 3단 계약을 통과했고 Number.isFinite(score)인 항 (score=0 계상 항 포함)
sum_score   = Σ valid_terms.score
sum_max     = Σ valid_terms.points
if (sum_max >= config.fov.rescale_min_max(15))  fov = round(clamp(0, 30, 30 * sum_score / sum_max))
else                                            result.mode = 'partial'   // 시야각 미표기
표기: "+N°" (0이어도 "+0° — 원래 넓으셨군요" 류, 음수 표기 없음)
```

**재스케일은 '미제시'에만 적용된다.** 항이 빠져도 상한 30이 유지되므로 기지자·절단자가 구조적으로 불이익을 받지 않고, 미응답은 0점으로 계상되므로 스킵이 이득이 되지도 않는다. `sum_max ≥ 15` 가드가 없으면 T4만 유효한 세션이 30점을 받는 사고가 나므로 하한을 둔다.

**전형값 감각 검증** — T1(`agree_pre≈0`, Δ≈20 → `room`=50 → `room_factor`=1 → 20/30) → 5.3 / T2 `brier`≈0.26·수축 후 0.258 → 4.85 / T3 `pre`=60·`post`=50·`room_conf`=50 → `drop`10/25 → 2.8 / T4 정답률 0.33 → 1.65. 합 **≈14.6**으로 목표 중앙값 12~18에 안착. 배점 상한(8/10/7/5)은 고정.

**자유 계수 = 시야각 7개 + 축 11개 = 18개.**
- 시야각 7: `delta_full`, `room_ref`, `conf_full`, `brier_max`, `brier_prior`, `drop_full`, `t3.conf_floor` (`trap_floor` 삭제, `shrink_k`는 수축 상수로 고정)
- 축 11: `axis_rhythm.cut_both / cut_behavior_only / cut_self_report_only`, `axis_conf.cut_lo / cut_hi`, `stall.norm`의 p1·p2·p4 각 lo·hi(6개)
- **역산 범위가 다르다**: 시야각 7개는 M2-a 합성 1,000건으로 초기값을 잡되, **축 11개와 참조분포는 합성 데이터로 정할 수 없다**(합성의 확신·갑작스러움 분포는 작성자가 넣은 가정이므로 순환 논리다). 축 계수는 **M2-b 실측 분위수**로 확정한다(§10). 역산 결과는 `CONFIG` 한 곳에만 반영하고 코드는 손대지 않는다.

### 6-3. 시야각 폴백 표

| 상황 | 감지 조건 | 폴백 |
|---|---|---|
| T1 — p5 미제시 | `p5_reframe.presented=false` | 항 제외 후 재스케일 |
| T1 — p5 제시·미응답 | `presented && !(touched_pre && touched_post)` | **`score=0` 항 유지** |
| T2 — 유효 항목 0, 소스 전량 미제시 | `n=0 && 모든 items presented=false` | 항 제외 후 재스케일 |
| T2 — 유효 항목 0, 제시됨 | `n=0 && 일부 presented=true` | **`score=0` 항 유지** |
| T2 — 유효 항목 1 | `n=1` | `shrink_k=2`로 수축 후 계산 + `low_n=true` |
| T3 — 사후항 결측 | p4 conf `touched=false` | p4 미제시면 항 제외 / 제시·미터치면 `score=0` 항 유지 |
| T3 — 이전 표본 0 | p1·p2 conf touched 0 | 항 제외 후 재스케일(**대체식 금지** — 구성이 달라진다) |
| T3 — 처치 무효 | `p3.known_before=true` 또는 `p3.presented=false` 또는 `p4.correct=true` | 항 제외 후 재스케일 (`no_treatment`) |
| T3 — 여지 없음 | `room_conf < min_room(8)` | 항 제외 후 재스케일 (`no_room`) |
| T4 — 시도 0, 소스 미제시 | `attempted=0 && 전량 presented=false` | 항 제외 후 재스케일 |
| T4 — 시도 0, 제시됨 | `attempted=0 && 일부 presented=true` | **`score=0` 항 유지** |
| 유효 배점 합 <15 | `sum_max < 15` | 시야각 미표기, `result.mode='partial'` |
| 분모 0 | 모든 비율 | 유효 조건에서 선차단. `safeDiv`의 `fb`가 발동하면 **버그**이므로 `degraded=true` + 항 제외 |
| 잔여 비수치 | `judge()` 반환 검증 | 숫자 필드가 `Number.isFinite`가 아니면 항 제외 + `degraded:true` 로깅 |

**폴백 판정 우선순위** — 한 세션이 한 항에서 복수 행에 동시 매칭되면(예: `p3.known_before=true`이면서 p4가 제시·미터치) **항 제외 사유(`no_treatment` → `no_room` → 소스 전량 미제시)를 먼저 적용**하고, `score=0` 항 유지는 어떤 제외 사유에도 해당하지 않을 때의 최후 규칙이다. 근거: 처치가 무효인 세션에서 0점을 계상하면 '측정 안 됨'이 '낮음'으로 둔갑해 §9의 감점 금지를 우회한다. 같은 우선순위를 `judge()` 구현과 셀프테스트 픽스처에 반영한다.

**`judge()` 계약** — 입력 = `(session JSON, config)`, 출력 = §7-2의 `result` 객체, **부작용 없음**(순수함수). 반환 직전 전 숫자 필드에 `Number.isFinite` 전수 검사를 돌린다.

**`?selftest=1` 극단 픽스처 8종(고정)** — ① 전항 만점 ② 전항 0 ③ **대체정답**(p1에 "빛" 입력 → `correct=true`) ④ `(n_stall, n_sudden) = (1,0)` ⑤ `(0,1)` ⑥ `(0,0)` + CNF n=0 → `minimal` ⑦ **한 축만 판정 + 함정 미도달**(`p3.presented=false`) → `partial` 헤드라인 검증 ⑧ 하드캡 절단(`cap_truncated=true`, p2 skip) + p5 보존. ③~⑧이 결측·폴백 케이스다.

## 8. 기술 요구사항

- **형태**: 단일 자기완결 `index.html`(바닐라 JS, 빌드 없음). 외부 CDN·외부 폰트·외부 API 호출 금지. **예외 2건뿐**: ① GA4 `gtag.js`(`googletagmanager.com`) ② M3 수집 엔드포인트(자체 도메인). 그 외 스크립트·폰트·이미지는 전부 인라인. 시스템 폰트 스택.
- **모바일 우선**: 기준 뷰포트 390px. 데스크톱은 중앙 카드 레이아웃.
- **언어**: 한국어 **전용**. 카피는 이 문서의 문구를 그대로 사용(특히 §4 P3 공개 화면).
- **무드**: v0.1 계승 — 어두운 배경 + 섬광 옐로 포인트. 심리테스트보다 실험실 톤.
- **접근성**: 모든 척도는 탭 입력, 색맹 대비 확보. 탭패드는 축 라벨을 항상 노출.
- **네비게이션**: 홈 링크 `../../index.html`. **iframe 임베드 요구는 삭제**(직링크 단일 페이지).
- **에셋**: 전부 코드 생성(SVG/canvas).

### 8-1. 타이밍·세션 규칙

- `visibilitychange` → 타이머 정지 + `hidden_spans` push + `hidden_ms` 누산(퍼즐 단위와 세션 루트 양쪽). 모든 stall/active 계산에서 차감한다. 시스템이 강제한 대기(공유 시트, 이미지 인코딩 등)는 `blocked_spans`에 별도로 적재해 함께 차감한다.
- `t_first_input`을 퍼즐마다 기록하고 타임박스 카운트다운의 기준으로 쓴다. 첫 입력이 없으면 화면 진입 + `idle_grace_s(20)` 후 시작. 화면 진입~첫 입력 간격은 `pre_input_gap_ms`로 따로 남긴다(§5-1 stall 후보에 포함되는 값이므로 반드시 기록).
- **세션 캡은 활성 시간 기준**이다: `active_total_ms = (now − ts_start) − session.hidden_ms − session.blocked_ms`. 캡 검사는 **화면 전환 시점에만** 수행한다(퍼즐 도중 화면이 사라지지 않게).
- **이어하기**: 마지막 저장이 2시간(`resume_ask_after_s`) 초과면 "이어할까요 / 새로 시작"을 묻고, 24시간(`resume_expire_s`) 초과면 무조건 새 세션(구 세션은 `dropped_at`을 찍고 보존). 재개는 **퍼즐 경계에서만** 허용한다. 퍼즐 중간 상태에서 재개하면 그 퍼즐은 `resumed_discard=true`로 표시하고 처음부터 다시 제시하며, 폐기된 시도의 타이밍은 축 계산에서 제외한다(백그라운드 체류 시간이 stall로 오염되는 것을 막는다).
- 새 세션을 시작할 때 `seeing-meta.play_index`를 +1 하고 그 값을 세션 루트에 복사한다.

### 8-2. GA4 이벤트 (`G-SF7BJ4211L`)

3중 가드 필수: **중복 방지 플래그 + `typeof gtag === 'function'` 체크 + `try/catch`**.

| 이벤트 | 발화 시점 | 파라미터 |
|---|---|---|
| `game_step` | 단계 진입마다 (인트로/사전/p1~p5/결과/동의) | `game_id:'seeing'`, `step`(화면 id), `play_index`, `lang:'ko'` |
| `game_complete` | 결과 카드 진입 1회 | `game_id:'seeing'`, `scene:'result'`, `result`(type_code 또는 `partial`/`minimal`), `lang:'ko'` |

`play_index`는 **세션 루트의 값**(`seeing-meta` 기준 누적 플레이 회차)을 보낸다. 퍼즐 순번(`order_index`)이 아니다. `game_complete`는 세션당 1회만 발화(플래그로 보장). `gtag` 부재나 예외는 게임 흐름을 절대 중단시키지 않는다.

### 8-3. 공유 카드

① **결과 진입 시 canvas 선렌더 + `File` 객체까지 미리 생성** — DPR 2배, `measureText` 기반 줄바꿈, `canvas.toBlob(b => file = new File([b],'seeing.png',{type:'image/png'}))`. 탭 시점에는 렌더도 인코딩도 하지 않는다. `toBlob`은 비동기이므로 탭 핸들러 안에서 부르면 `await`가 개입해 iOS의 사용자 제스처 컨텍스트가 소실된다. ② 탭 핸들러에서 `navigator.canShare?.({files:[file]})`로 **동기 사전 검사** 후 **`await` 없이** `navigator.share({files:[file]})` 호출(반환 프라미스의 rejection은 `.catch`로만 처리). ③ 미지원·거부·예외 시 `a[download]` 폴백. ④ 인앱 웹뷰(UA 목록은 `config.share.inapp_ua`: KAKAOTALK / Instagram / FBAN / FBAV / Line)에서는 **② 단계를 건너뛰고** 바로 이미지를 표시하며 "길게 눌러 저장"을 안내한다. ⑤ **카드 이미지 안에 URL 텍스트를 포함**한다(`game.in-9.com/puzzle/seeing/`).

### 8-4. M3 수집 (Worker + D1)

- `POST /api/seeing/session` — 기존 `worker/index.js`에 라우트 추가. 현재 `worker/index.js:14`의 `ROOM_PATH = /^\/api\/room\/([A-Za-z0-9]{1,12})$/` 하나만 가로채고 있음을 확인했으므로 **경로 충돌 없음**.
- 저장소는 D1. `consent.research === true`일 때만 전송. **IP·개인식별정보 미저장.**
- `wrangler.jsonc`에 바인딩을 추가해야 한다(누락 시 `env.SEEING_DB`가 `undefined`라 런타임에서만 터진다):

```jsonc
"d1_databases": [
  { "binding": "SEEING_DB", "database_name": "seeing", "database_id": "<wrangler d1 create 출력>" }
]
```

```sql
CREATE TABLE IF NOT EXISTS sessions (
  session_id     TEXT PRIMARY KEY,
  config_version TEXT NOT NULL,
  ts_start       INTEGER NOT NULL,
  age_band       TEXT,
  payload        TEXT NOT NULL,
  received_at    INTEGER NOT NULL
);
```

- Worker 가드: `Content-Length > 65536` → 413 / `Origin`이 `https://game.in-9.com`이 아니면 403 / `INSERT OR IGNORE`로 `session_id` 멱등 처리(재시도 중복 방지) / IP 해시 없는 단순 레이트 리밋. **성공·실패 무관하게 204를 반환**하고, 클라이언트는 응답을 기다리지 않는다(수집 실패가 결과 화면을 막으면 안 된다).
- **동의 화면은 결과 카드 뒤에 배치**한다(자기 데이터를 본 뒤 결정하므로 정보에 근거한 동의가 되고, 흐름도 끊기지 않는다). 같은 화면에 **연령 밴드**(~12 / 13~18 / 19~)와 **만 14세 미만 보호자 안내 고지**를 넣는다.
- **`age_14_plus` 게이트**: 밴드가 `13~18`이면 "만 14세 이상인가요?"를 1탭으로 확인한다(만 14세 미만이 이 밴드에 섞이기 때문). `age_band === '~12'` 이거나 `age_14_plus === false`면 전송 버튼을 숨기고 보호자 안내 + "이 기기에만 저장하기"만 노출한다. Worker는 `age_14_plus === true`가 아닌 payload를 저장 없이 204로 폐기한다(클라이언트 우회 방지).

### 8-5. CATALOG 등록 (M2-b 완료 시)

`index.html`의 CATALOG 배열에 그대로 추가한다. 필드명은 **`t`(제목) / `d`(설명)**이며 언어 오브젝트가 하나라도 빠지면 `index.html:815 renderGrid()`가 `undefined.t` 접근에서 예외를 던져 **포털 그리드 전체가 빈 화면이 된다**. 3개국어를 반드시 채운다.
